# 결과보고서

- 저장 파일: report.md, 기존 결과보고서가 있으면 해당 위치 유지
- 작업 기록, 의도, SDD와 구현 기록: 실제 상대 링크로 연결
- 기준 사양 버전, 보고 대상 코드 상태와 환경:
- 보고 구분: 중간, 부분 완료, 최종 중 실제 해당하는 상태
- 구현 상태: 미확인
- 자체 검증 상태: 미확인
- 독립 검증 상태: 미실행
- 배포 상태: 미실행

## 달라진 결과

- 사용자가 관찰할 수 있는 변경:
- 이번에 실제 완료한 범위와 제외한 범위:
- 실행 방법과 결과를 확인한 환경:
- 지금 사용할 수 있는 범위, 추가 연결이나 릴리스가 필요한 부분:

## 인수 조건별 판정

| 인수 조건 ID | 요구한 결과와 실제 결과 | 판정 | 구현 기록의 실행 ID 또는 정적 근거 | 미확인과 다음 조치 |
| --- | --- | --- | --- | --- |

검사 범위에서 조건 충족, 문제 발견, 검증 불가와 재검증 필요를 구분한다. 단위 검사 통과를 사용자 경계 전체의 성공으로 확대하지 않는다.

## 독립 검증

- 검증 담당과 새 컨텍스트 여부:
- 검증한 사양 버전과 대상 코드 상태:
- 실행 또는 정적 검토 범위와 근거 위치:
- 확인된 결함, 정적 근거와 미확인 위험:
- 재검증 판정과 이전 결과를 대체하는 이유:

독립 실행 근거는 implementation.md에 실행 ID로 보관하고 여기는 판정과 링크를 남긴다. 새 검증자를 실행하지 못하면 미실행 이유와 다음 조치를 적고 독립 검증 완료로 표시하지 않는다.

## 사양과 구현의 차이

- 사용자 승인으로 바뀐 계약과 관련 변경 이력 위치:
- 현재 코드와 정본이 일치하는 근거:
- 아직 반영하지 못한 차이와 실제 영향:

## 남은 일과 마감

- 실패 또는 미실행 필수 검사, 재현과 필요한 환경:
- 남은 질문, 사용자 보류와 재개 조건:
- 범위 밖 발견과 후속 작업 후보:
- 다음 행동, 사용자에게 필요한 결정:
- 배포했다면 실제 배포 근거, 실행하지 않았다면 미실행:

코드 변경 시 이전 검증 대상과 근거는 보존하고 영향받는 현재 판정은 재검증 필요로 바꾼다. 최종 보고 전 이 문서와 task.md의 상태를 맞춘다. 구현, 검증, 배포를 각각 판단하며 미실행을 완료로 바꾸지 않는다.
