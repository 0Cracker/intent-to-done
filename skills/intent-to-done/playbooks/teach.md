# Teach

코드와 변경을 이해하도록 설명한다. 기본은 주 담당 실행이다. how와 why의 기존 근거를 재사용하며 두 기능의 실행이나 에이전트 분리를 강제하지 않는다.

1. 질문과 맥락에서 판단과 이해의 핵심을 찾는다. 이미 아는 것을 재시험하지 않는다.
2. 무엇이며 이번 작업에서 어떤 일을 하는지 쉬운 한두 문장으로 설명한다.
3. 사용자 행동을 따라 실제 동작을 보여준다. 함수와 상수를 나열하기보다 원인과 결과를 연결한다.
4. 그림이 도움이 되는 복잡한 설명은 작은 흐름부터 필요한 요소를 덧붙인다. 간단한 사실은 그림 없이 설명할 수 있다.
5. 자세한 질문이 오면 해당 층을 설명한다. 쉬운 말로 바꿔도 원래 why 근거의 불확실성은 보존한다.

[보고 규칙](../references/reporting.md)을 따른다. 과한 비유, 어린아이를 대하는 말투와 이해 확인 시험을 기본으로 쓰지 않는다. 설명만 요청하면 제품 코드를 수정하지 않는다. 매 답변에 별도 이미지 모델과 HTML 생성을 강제하지 않는다.
