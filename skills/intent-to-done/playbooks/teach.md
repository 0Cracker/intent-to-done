# Teach

사용자가 코드나 변경을 이해하도록 설명한다. 기본은 주 담당 실행이다. how와 why의 확보된 근거를 재사용하며 두 기능을 무조건 실행하거나 에이전트로 분리하지 않는다.

1. 사용자가 판단하거나 이해해야 할 핵심을 현재 질문과 맥락에서 찾는다. 이미 아는 것을 재시험하지 않는다.
2. 먼저 무엇인지와 이번 작업에서 하는 일을 쉬운 한두 문장으로 설명한다.
3. 사용자의 행동을 따라 실제로 무엇이 일어나는지 보여준다. 함수와 상수 나열보다 원인과 결과를 연결한다.
4. 그림이 이해를 돕는 복잡한 설명은 작은 흐름부터 보여주고 필요한 요소를 덧붙인다. 간단한 사실은 그림 없이 설명할 수 있다.
5. 더 자세한 질문이 오면 해당 층을 설명한다. 원래 why 근거의 불확실성을 쉬운 말로 바꾸면서 제거하지 않는다.

[보고 규칙](../references/reporting.md)을 따른다. 과한 비유와 어린아이를 대하는 말투, 이해 확인 시험을 기본으로 사용하지 않는다. 설명만 요청했으면 제품 코드를 수정하지 않는다. 별도 이미지 모델과 HTML 생성을 매 답변에 강제하지 않는다.
