# 독립 검증과 마감

변경은 자체 검증과 별도로 새 컨텍스트의 검증자 한 명에게 확인시킨다. 이 스킬은 해당 위임을 요청한다. 추가 검토자가 필요해도 주 담당 포함 동시 총 3개 상한을 지킨다.

## 검증자에게 전달할 것

- 원래 요청과 확정 사양, 인수 조건, 제약과 비목표.
- 저장소와 대상 파일, 비교할 기준과 대상 코드 상태, 재현 가능한 실행 방법.
- 알려진 기존 실패와 환경 제한, 이전부터 이어진 같은 문제의 수정 횟수.
- 작업 문서 경로와 승인된 사양 버전, 인수 조건별 테스트와 실행 근거 위치. 검증 결과는 주 담당에게 반환하고 정본은 주 담당이 갱신한다.

구현자의 “잘 됐다”는 결론을 정답으로 주지 않는다. 테스트와 실제 코드는 읽게 하고 전체 대화와 불필요한 파일은 복제하지 않는다. 검증자는 제품 코드 수정과 무허가 재위임을 하지 않는다. 격리된 재현 스크립트와 검사는 권한 내에서 실행할 수 있다.

새 컨텍스트의 검증자를 실행할 수 없으면 같은 세션의 재검토를 독립 검증이라 하지 않는다. 다른 세션에 넘길 짧은 검증 요청을 준비하고 실행 전까지 검증 완료를 보류한다.

## 확인할 내용

1. 사양의 각 조건을 실제 구현과 테스트에 대조한다.
2. 중요한 입력, 실패와 인접 경로, 기존 계약의 회귀를 관련 범위에서 확인한다.
3. 기대값과 검사가 구현을 따라 썼는지, 실제 동작을 검사하는지 검토한다.
4. UI 실제 조작, API 요청과 응답 등 대상의 실제 경계에서 확인한다. 다른 대상의 검사 결과로 대체하지 않는다.
5. 확인된 결함은 재현 명령, 실제와 기대 결과, 영향과 코드 위치를 보고한다. 실행 불가와 미재현 위험도 결함과 구분해 알린다.

정적으로 명백한 문제는 경로와 근거를 제시하고 실행 재현 여부를 별도로 표시한다. 실행 여부만으로 의미 있는 미확인 위험을 삭제하지 않는다.

## 결과와 수정

결과는 “조건 충족”, “문제 발견”, “검증 불가”로 구분하고 범위와 실행 근거를 적는다. “조건 충족”은 검사 범위에 한정하며 무결함을 보장하지 않는다. 단위 검사와 빌드 통과로 사용자 경험 전체의 성공을 선언하지 않는다.

문제는 주 담당이 확정 사양 안에서 수정한다. 같은 문제의 수정 횟수는 구현 중 자체 검증부터 합산한다. 변경 후 영향받는 조건을 재검증하며 이전 판정을 새 코드에 그대로 쓰지 않는다.

필수 검증을 못 했거나 두 차례 수정 후에도 실패하면 구현 상태, 근거, 보류 이유와 다음 조치를 보고한다. 검증 완료로 표시하지 않는다. 무관한 기존 실패를 명시하고 프로젝트의 필수 통과 조건을 따른다.

기본 모드에서는 사용자가 독립 검증 결과를 판단한 뒤 완료 보고로 넘어간다. 자동 진행 범위면 결과에 따라 마감한다.

문서 모드에서는 [결과보고서 템플릿](../assets/report-template.md)으로 `report.md`에 검증 담당, 대상 코드 상태, 사양 버전, 인수 조건별 판정과 근거 링크를 저장한 뒤 사용자 판단을 요청한다. 독립 실행 상세는 `implementation.md`에 실행 ID로 추가한다.

코드가 바뀌면 이전 근거는 보존하고 영향받는 현재 판정을 재검증 필요로 바꾼다. 다음 수정과 마감 전 사용자 판단과 새 진행 범위를 `task.md` 결정 이력에 남긴다. 기존 결과 정본은 해당 위치에서 이어 쓴다.

## 마감

변경된 계약과 상태를 정본에 갱신한다. 최종 보고 전 `report.md`에 변경 결과, 실제 사용 방법, 검증과 미확인, 남은 일을 저장한다. `task.md`의 마감 상태와 다음 행동도 맞춘다.

독립 검증 불가나 중간 마감 시 보고서는 부분 결과로 작성하고 구현, 검증, 배포를 각각 판단한다. 최종 답변에 결과보고서 경로를 포함한다. 사양 밖의 변화와 미해결 결함을 숨기지 않는다. 맡겨지지 않은 병합, 배포와 외부 전송으로 범위를 넓히지 않는다.
