# Why

현재 설계의 이유를 조사한다. 기본은 주 담당 실행이며 출처별 조사자를 자동 생성하지 않는다.

1. 대상 코드와 결정, 사용자의 질문을 특정한다.
2. Git 이력, blame, 테스트와 결정 문서부터 조사한다. 필요하면 연결된 PR, 이슈와 이용 가능한 관련 자료로 넓힌다.
3. 최근 수정을 최초 설계 이유로 단정하지 않는다. 과거 기록과 현재 코드를 대조한다.
4. 확인한 이유, 합리적 추론, 대안 가설과 미확인을 구분한다. 필요한 주장에 근거 링크나 코드 위치를 연결한다.
5. 변경을 위한 조사라면 유지할 제약, 바꿀 부분과 위험을 짧게 정리해 SDD 인터뷰에 전달한다.

코드만 보고 작성자의 의도와 과거 사고를 지어내지 않는다. 검색할 자료가 없으면 한계를 알린다. 모든 연결 서비스를 매번 전수 검색하지 않는다. 조회 권한은 외부 메시지 전송과 수정 권한이 아니다.
