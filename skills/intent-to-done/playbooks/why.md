# Why

현재 설계가 생긴 이유를 조사한다. 기본은 주 담당 실행이며 출처별 조사자를 자동 생성하지 않는다.

1. 대상 코드와 결정, 사용자의 질문을 특정한다.
2. 관련 Git 이력과 blame, 테스트, 결정 문서부터 조사한다. 필요하면 연결된 PR과 이슈, 사용 가능한 관련 자료로 넓힌다.
3. 최근 수정이 최초 설계 이유라고 단정하지 않는다. 과거 기록이 현재 코드와 어떻게 이어지는지 대조한다.
4. 확인한 이유, 합리적인 추론, 대안 가설과 알 수 없는 부분을 구분한다. 근거 링크나 코드 위치를 필요한 주장에 연결한다.
5. 변경을 위한 조사라면 유지할 제약, 바꿀 수 있는 것, 위험을 짧게 정리해 SDD 인터뷰의 근거로 전달한다.

코드가 그렇게 보인다는 이유만으로 작성자의 의도와 과거 사고를 지어내지 않는다. 검색 가능한 자료가 없으면 제한을 알린다. 모든 연결 서비스를 매번 전수 검색하지 않는다. 자료 조회 권한이 외부 메시지 전송이나 수정 권한을 뜻하지 않는다.
