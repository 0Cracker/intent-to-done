# 쉬운 보고와 시각화

주 담당이 사용자 보고를 정리한다. 보조는 근거와 결과를 짧게 전달하되, 확인하지 않은 것을 통과로 요약하지 않는다. 별도 설명용 에이전트를 항상 호출하지 않는다.

## 기본 보고

첫 문장에 결과나 필요한 결정을 담는다. 한 화면에서 판단할 수 있는 길이를 목표로 하고, 해당하는 항목만 사용한다.

- 결론: 이번 단계에서 정리된 것과 현재 상태.
- 바뀌는 점: 사용자가 경험할 변화.
- 판단할 것: 실제 선택지, 영향과 추천 이유.
- 중요한 한계: 실패, 미실행, 미확인, 비용과 데이터 영향.
- 다음 단계: 진행하면 무엇을 하는지.

세부 코드와 전체 로그는 연결하고 앞에서 장황하게 나열하지 않는다. 짧게 보고하려고 조건과 위험을 숨기지 않는다. 첫 실행 로그와 기대 출력 예시를 혼동하지 않는다. 보고와 상태 기록에 쉼표를 사용하고 가운뎃점을 쓰지 않는다.

## 그림과 설명

eli5의 큰 그림과 적은 글자를 적용한다. 배경지식 없이도 이해할 수 있게 용어를 필요한 만큼 설명하며, 어린아이를 대하는 말투와 과장된 비유를 사용하지 않는다.

- 짧은 동작 흐름과 구조: 작은 Mermaid.
- 선택지와 차이: 간단한 표.
- 화면 변화: 실제 변경 전후 캡처. 목업이면 목업이라고 표시.
- 공간 관계와 복잡한 단계 설명: 필요할 때 큰 그림과 짧은 라벨의 HTML.
- 단순한 결과: 짧은 문장만으로 충분.

이미지를 생성하거나 HTML을 매 단계 만들 필요는 없다. 기존 화면 도구와 캡처, Mermaid와 HTML 중 현재 환경에서 확인 가능한 수단을 사용한다. 그림과 본문에 같은 내용을 길게 반복하지 않는다. HTML 등 새 시각 자료는 표시 가능성과 내용, 잘림과 가독성을 확인한다. 확인하지 못하면 그 한계를 알린다.

## 테스트 보고 예시

아래는 형식 예시이며 실제 실행 결과가 아니다.

> 목표: 상세에서 목록으로 돌아오면 선택한 정렬 유지.
>
> 시나리오: 오름차순 선택 → 상세 진입 → 목록 복귀.
>
> 기대: 선택과 목록 순서 유지.
>
> 실제: 실행한 결과와 실패 이유 또는 통과 기준선.
>
> 근거: 실행 명령과 코드 상태, 로그나 캡처 링크.
>
> 다음: 기본 모드이면 사용자 판단 후 구현.

사용자가 답할 질문은 환경의 질문 도구가 있으면 그 도구로 제시한다. 없으면 짧은 번호 질문으로 묻고 답을 기다린다. 중요한 선택의 침묵을 추천안 수락으로 취급하지 않는다.
