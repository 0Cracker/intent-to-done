# 작업 상태와 재개

작업 범위를 넘는 관리 체계를 만들지 않는다. 짧은 작업은 대화로 충분하다. 여러 단계와 세션, 인계가 있는 작업은 기존 작업 문서 한 곳에 아래 필요한 항목을 유지한다.

| 항목 | 남길 내용 |
| --- | --- |
| 현재 상태 | 단계, 진행 중 또는 사용자 판단 대기, 중단 이유 |
| 요청과 정본 | 원래 요청 요약, 사양과 계획의 위치와 변경 식별 |
| 결정 | 확정, 추천, 미결과 사용자 보류를 구분한 현재 결정 |
| 진행 권한 | 수동 또는 자동 구간, 별도로 위임한 결정권의 범위 |
| 코드 상태 | 저장소, branch와 HEAD, 관련 미커밋 변경과 사용자 변경 |
| 검증 | 인수 조건별 검사와 실제 결과, 대상 코드 상태와 환경, 기존 실패와 미확인 |
| 수정 횟수 | 근본 문제별 수정과 재검증 횟수, 각 시도 근거 |
| 다음 행동 | 남은 질문, 필요한 환경과 승인, 다음 실행 지점 |

임시 placeholder를 사실로 채우지 않는다. 간단한 인수 조건에는 식별자를 부여해 테스트와 연결할 수 있다. 별도 대장이나 새 문서를 필수로 만들지 않는다.

재개할 때 실제 코드와 문서, 사용자의 최신 지시를 대조한다. 승인과 보류를 보존하고 달라진 범위만 재확인한다. 문서의 완료 표시만으로 현재 코드의 완료나 검증 통과를 단정하지 않는다. 코드가 바뀌면 영향을 받는 검사 근거를 갱신하며 유효한 다른 결정을 전부 초기화하지 않는다.

순수 사양 변경이 생기면 영향을 받는 테스트와 구현 계획을 함께 갱신한다. 같은 근본 문제의 자동 수정 횟수는 이어간다. 사용자가 추가 수정을 지시하면 그 새 범위를 기록한다. 요약 과정에서 미결과 미확인, 자동 진행 권한의 경계를 제거하지 않는다.
